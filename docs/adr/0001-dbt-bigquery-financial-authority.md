# 以 dbt／BigQuery 作為雲端財務指標的權威來源

2026-11-07：採納使用者確認的方向，將雲端 Loan Review 共用的財務來源選取、期間配對、公式計算與資料驗證移至 dbt models／tests，由 BigQuery 執行；Python 負責資料擷取、調度、文字分析、契約轉接與報告交付。目的是讓報告、Dashboard 與 BI 使用同一份有版本、可追溯的財務結果，避免各消費端自行維護不同公式。

這是目標架構決策，已開始影子計算與驗證，尚未完整實作或切換；公式、公司個別定義及驗收標準不因技術遷移而改變。具體計算契約、精度提案、比對與切換條件見 [遷移規格](../specs/dbt-financial-calculation-migration.md)。精度方案與切換放行必須完成該規格的決策及驗證，不能僅憑本 ADR 視為已批准。

## 考慮過的方案

- 維持 Python 為唯一計算來源：可離線執行、重用現有契約，但倉儲指標依賴報告程式產出，BI 不容易獨立重用計算流程。
- Python 與 dbt 長期雙重權威：維持兩條路的彈性，但容易出現定義與數值差異；不採用。
- 採用 dbt／BigQuery 為雲端權威：接受雲端依賴及契約轉接成本，以換取集中管理的財務資料模型。Python 計算器只在遷移期間作比較基準，或在明確標示的本機模式使用。

## 影響

- 候選計算結果必須能在驗收前入倉；正式消費端僅能讀取通過發布門檻的結果。dbt test 成功本身不等於財務驗收或報告交付成功。
- 雲端不得靜默退回 Python 計算，也不得直接沿用 Legacy KPI 的代理定義；離線結果不可冒充雲端發布成果。
- 遷移後 Python 仍驗證來源、結構、證據連結及交付物，但不再以舊 Decimal 計算結果作為雲端數值的唯一裁決者。
- 已發布的 run 不隨後續公式、來源、政策或 dbt rebuild 改變；更動需產生新計算版本與執行紀錄。
